# Hivemind — Phase 4 spec: Conversations everywhere + "Hive", the conductor (release 2.4.0)

User ask (2026-11-25): "make sure the conversations are conversable through the app… when sending a command
you get the output but no chance to send anything back… maybe a tutorial… KISS, abstracted from user, genius
under the hood" and "like OpenAI Dot / Claude Duet: one that can spawn agents… multi-machine wide".
Builds on 2.3.0 (Today, Ask box, Activity, sessions/transcripts, continue/resume, admin lane, alerts).

## C. Every task is a conversation
C1. **Session-backed tasks.** Claude tasks start with `claude -p --session-id <uuid generated by hub>
--output-format stream-json --verbose` (stream parsed into the same transcript events as sessions; final
`result` captured); Codex tasks with `codex exec --json` (thread id captured from the first event). The job row
stores `session: {tool, session_id}`; the session index links it to the job's project. PowerShell tasks stay
one-shot (reply box offers "Run another command").
C2. **Reply = continue.** Any finished (or idle) task/session shows a reply box. Sending creates a resume job
on the SAME node + cwd (`claude -p --resume <id>`, `codex exec resume <id> -`), appended to the same
conversation thread in the UI — the user just sees one chat. While a turn runs, the box shows "Working…" with
Stop; a reply typed during a turn is queued and sent when it finishes.
C3. **Live streaming.** Running tasks stream into the chat via the transcript channel (assistant text,
collapsed tool chips, "thinking" hidden), not raw stdout. Raw output stays available under "⋯ → Raw log".
C4. **Needs-input detection.** When a turn ends with a question to the user (assistant's final message ends
with "?" or the CLI reports a permission denial / user-input request), the conversation is marked
**Needs you** (Today card + optional notification "forge-03 is asking: …").
C5. **One conversation model in the UI.** Tasks, sessions and Hive chats are all "Conversations" with the same
view: header (title · machine · project · status), chat, reply box, ⋯ menu (Open in T3, Raw log, Full access,
Move to another machine = start a new session there seeded with a summary).

## H. Hive — the conductor
H1. **What it is.** One long-lived Claude Code conversation ("Hive") running on the leader's best-fit node in
auto permission mode, with the **Hivemind MCP server** attached. It is the Ask box: you talk to Hive; Hive
plans, spawns agents on any machine, watches them, answers you, and summarises. Each Hive turn is a normal
resumable session (C1/C2), so Hive's own history persists and survives failover (session file lives on the
node; hub keeps the session id; if that node is gone, Hive restarts on another node seeded with the last brief
+ recent turns summary).
H2. **Hivemind MCP server** (`hub/mcp/` stdio server, Python, launched by claude via `--mcp-config`; talks to
the local hub with a scoped *hive token*). Tools (all return compact JSON):
- `fleet_status()` — machines (online, busy, GPU, free disk), alerts that need the user.
- `list_projects(query?)`, `project_brief(project)`, `list_conversations(project?, state?)`,
  `read_conversation(id, last_n=20)`.
- `spawn_agent(prompt, project?, cwd?, machine="auto", engine="best", kind="code", notify=false)` → conversation id.
- `send_to_conversation(id, message)` (continue/resume), `stop_conversation(id)`.
- `wait_for(ids, timeout_s<=600)` → statuses + last assistant message of each.
- `run_maintenance(action, args, targets)` → requires the user's confirmation in the UI (Hive can only *propose*
  admin/destructive actions; the UI shows "Hive wants to: … [Approve] [Deny]", PIN applies).
Guardrails: max 6 concurrent Hive-spawned agents (config), every spawned conversation tagged
`parent: hive-turn-id` so the UI nests them under the Hive message that created them; no SYSTEM-lane access.
H3. **Hive's prompt** (system prompt appended via `--append-system-prompt`): role (conductor for this user's
fleet), use tools instead of guessing, prefer spawning parallel agents for independent work, report concisely,
always say which machine is doing what, ask before anything destructive, never claim a sub-agent finished
without `wait_for` evidence.
H4. **UI.** The Ask bar opens the Hive chat (full-screen on phone). Hive messages render spawned agents as live
child cards ("🟢 forge-03 · Claude · writing tests…") that open their own conversation. Voice: iOS keyboard
dictation works; a 🎤 button uses the Web Speech API where available (progressive enhancement).
H5. **Proactive mode** (off by default, toggle): Hive reads the morning brief + overnight alerts and posts a
short "Good morning" message with suggested next steps (one tap to start each).

## T. Tutorial / first-time guidance (KISS)
T1. **3-step coach marks** on first visit (dismissible, never again): "1 Ask Hive anything → 2 Watch agents work
on your machines → 3 Reply anytime to keep going." Replayable from ⋯ → "Show me around".
T2. **Empty states that teach**: Today with no conversations shows 3 example prompts as chips
("Summarise what changed in my repos today", "Run the tests in <top project> on any free machine",
"What's using the most disk across my machines?") — tap to send to Hive.
T3. **Inline hints** only where a first action is ambiguous (reply box placeholder: "Reply to keep going —
it picks up right where it left off").

## I. Machine icons (installer-owned, every node)
I1. The installer (and every self-update) maintains two shortcuts on the user's Desktop and Start Menu\Hivemind:
**Hivemind** (opens http://localhost:8787) and **Hivemind – Update & Repair** → `%ProgramData%\Forge\bin\
hivemind-repair.ps1` (admin+SYSTEM writable only): self-elevates once, finds a healthy hub from agent-config
`hub_urls`, re-runs the idempotent installer, opens the dashboard. Hand-placed on all 4 nodes 2026-11-25.
I2. Repair must keep working after 2.3.0 enrollment codes: the repair path authenticates with this node's own
agent token (node already enrolled) — the hub must keep `GET /agent/install.ps1?t=<agent_token>` for enrolled
nodes, or the repair script requests a code with its agent token first.
I3. Remove legacy icons ("Install Hivemind.cmd", "Hivemind.url"); never delete user-made shortcuts.

## Acceptance
- Send a Claude task from the phone → see streamed chat → reply twice → all three turns in one conversation,
  same session id on the same machine; same for Codex.
- Ask Hive "run the tests in <project> on two machines and tell me which is faster" → Hive spawns 2 agents on
  different machines, waits, answers with evidence; both child conversations are openable and continuable.
- Hive proposes an admin action → Approve/Deny card; nothing runs without approval.
- Kill Hive's node → next message to Hive works (restarted elsewhere with context summary).
- First-visit coach marks + example prompts appear once; ≤ 3 taps for each acceptance flow on a 390 px phone.
